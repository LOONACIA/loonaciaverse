이 사이트(LOONACIAVERSE)는 Claude Code가 계획과 리뷰를 맡고 Codex가 구현을 맡는 방식으로 만들었다. 스텝마다 Codex를 새 세션으로 실행해 테스트를 확인하고, Claude가 diff를 리뷰해 통과시킨 뒤에만 커밋한다. 그렇게 만들면서 걸렸던 부분들을 기록한다.

## 리뷰에서 걸러낸 것

테스트는 모두 통과했지만 리뷰에서 다시 시킨 경우들이다.

1. 셰이더의 노이즈 해시 함수에 코덱스가 "외부 소스 없음"이라는 주석을 달아 놨다. 그런데 상수와 계산 구조가 널리 알려진 공개 셰이더 코드와 똑같아서 원작자와 라이선스를 주석에 남기게 했다.

2. 콘텐츠 로더는 `OperationCanceledException`을 모두 잡고 있었다. 이러면 HttpClient 요청이 시간 초과로 취소됐을 때 로딩 표시가 사라지지 않는다. 테스트에는 이 경우가 없었다. 컴포넌트가 사라진 뒤에만 결과를 무시하고, 그 전에 난 오류는 SIGNAL LOST 화면과 RETRY 버튼으로 보여 주도록 고쳤다.

3. 문서를 고치는 스텝에서는 "실제 구현에 맞춘다"며 아직 구현하지 않은 설계를 지워 버렸다. 그래서 다음 계획부터는 스텝 설명에 "아직 구현하지 않은 설계는 지우지 마라"를 넣었다. 마지막 계획에서 코덱스는 지시대로 설계는 남겼지만, 이번에는 규칙을 지웠다. OG 태그에 사이트 값을 직접 적어야 하는 예외를 문서에 쓰면서, "코드에 하드코딩하지 않는다"는 원래 규칙을 지우고 그 자리에 예외 문장을 넣은 것이다. 원래 규칙은 그대로 두고 예외만 덧붙이게 했다.

## 하네스를 돌리며 겪은 문제

1. 코덱스가 확인용으로 vite dev 서버를 띄워 둔 채 일을 끝내면 코덱스의 프로세스가 종료되지 않았다. 그대로 두면 하네스는 스텝 타임아웃(30분)까지 기다린다. Windows에서는 셸이 끝나도 그 아래에서 뜬 node 프로세스가 살아남아 출력을 붙잡고 있는 것으로 보이는데, 남은 프로세스를 직접 죽이면 코덱스도 바로 끝났다. AGENTS.md에 "띄운 프로세스는 자식까지 종료하고 끝낸다"는 규칙을 넣은 뒤로는 코덱스가 vite를 알아서 껐다.

2. 재시도 피드백에 이전 시도의 diff 파일 경로를 적고 참고하라고 했는데, 코덱스는 그 파일을 읽지 못했다. 코덱스가 계획과 실행 기록을 건드리지 못하게 `.harness/` 접근을 훅으로 막아 둔 게 원인이었다. 그 뒤로는 클로드가 유지할 구현의 핵심을 피드백에 글로 직접 적도록 만들었다.
