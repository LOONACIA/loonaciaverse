# PRD: Loonaciaverse

> Claude는 `/harness plan` 때 이 문서를 읽고, 각 스텝의 description에 관련 섹션을 "읽어야 할 파일"로 적습니다.
> 화면·연출의 세부 명세는 [UX.md](UX.md), 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 되돌리기 어려운 결정은 [ADR.md](ADR.md)에 있습니다.

## 목표
C#/.NET·Unity 개발자의 포트폴리오 겸 기술 블로그를 "나를 중심으로 도는 항성계를 탐험한다"는 우주 컨셉 사이트로 만든다. 사이트 자체를 .NET 웹 개발(Blazor) 학습의 결과물로 삼는다.

## 사용자
1. **채용 담당자·면접관 (1순위)**: 메신저나 이력서의 링크로 들어오고, 모바일에서 여는 경우가 많다. 짧은 시간 안에 "무엇을 만들었고 무엇을 잘하는지" 파악해야 한다. 연출이 정보 접근을 방해하면 안 된다.
2. **기술 블로그 독자 (1순위)**: 검색이나 공유 링크로 글 상세에 바로 들어온다. 우주 화면을 거치지 않아도 글을 읽고 다른 글로 이동할 수 있어야 한다. RSS로 구독한다.
3. **사이트 주인**: 저장소에 Markdown을 쓰고 main에 푸시하면 발행된다. 관리자 화면은 없다.

## 핵심 기능

### 1. 우주 메인 화면
중심 항성(About), Projects 행성, Blog 행성, 잠긴 Playground 행성으로 이루어진 3D 항성계. 천체를 선택하면 카메라가 줌인하고 HUD가 열리며, TRAVEL을 누르면 워프 연출 뒤 상세 페이지로 이동한다. 세부 사항은 UX.md의 "메인 화면" 절을 따른다.

완료 판정 기준:
- `/`에서 천체 4개가 보이고 행성 3개가 항성 주위를 천천히 공전한다.
- 천체를 클릭(탭)하면 URL이 `/?focus={id}`로 바뀌고 카메라가 줌인하며 HUD가 열린다. 뒤로가기를 누르면 HUD가 닫히고 줌아웃된다.
- `/?focus=blog`로 직접 들어오면 Blog 행성에 포커스된 상태로 시작한다.
- HUD 스탯(글 수, 최신 글 날짜, 프로젝트 수, 대표 프로젝트 등)이 콘텐츠 인덱스에서 자동으로 계산된다.
- TRAVEL을 누르면 1초 이내의 워프 연출 뒤 해당 상세 페이지로 이동한다.
- Playground 행성은 선택할 수 있지만 HUD에 COMING SOON이 표시되고 TRAVEL은 비활성이다.
- 키보드만으로 천체 선택(Tab/방향키), HUD 열기·TRAVEL(Enter), 닫기(Esc)가 가능하다.

### 2. 프로젝트 목록·상세
완료 판정 기준:
- `/projects`에 카드 목록이 보인다. `featured` 프로젝트가 먼저 나오고 나머지는 `order` 순이다.
- `/projects/{slug}`에 케이스 스터디가 보인다: 기간, 역할, 기술 스택, 외부 링크(front matter), 그리고 본문(개요, 문제와 해결, 결과, 스크린샷, YouTube 임베드).
- 존재하지 않는 slug는 404 페이지를 보여 준다.

### 3. 블로그
완료 판정 기준:
- `/blog`에 날짜 내림차순 글 목록이 보인다(날짜, 제목, 요약, 태그).
- `/blog/tags/{tag}`에 해당 태그 글만 보인다.
- `/blog/{slug}`에 글이 보인다. 헤딩으로 만든 목차가 있고, 코드 블록은 highlight.js로 하이라이트된다.
- 빌드 산출물에 `feed.xml`(RSS 2.0)이 있고, 초안을 뺀 모든 글이 들어 있다.

### 4. About (중심 항성)
완료 판정 기준:
- `/about`에 이름, 직함, 주 기술 스택, 소개 본문, 이메일과 GitHub·LinkedIn 링크가 보인다.

### 5. 대체 경로와 접근성
완료 판정 기준:
- WebGL을 쓸 수 없거나 `prefers-reduced-motion: reduce`이면 홈이 3D 대신 목록형 내비게이션을 보여 준다.
- 모든 상세 페이지에 HUD형 상단 바(로고는 우주로 복귀, PROJECTS / BLOG / ABOUT)가 있다.
- 부팅 화면 마크업에 상세 페이지로 가는 일반 링크가 있어서 JS를 실행하지 않는 크롤러도 링크를 따라갈 수 있다.

### 6. 콘텐츠 파이프라인
완료 판정 기준:
- `content/`의 Markdown과 YAML이 `dotnet build` 때 `wwwroot/content/`의 JSON·HTML로 변환된다.
- `draft: true`인 글과 프로젝트는 Release 빌드에서 빠지고, Debug 빌드에서는 DRAFT 표시와 함께 보인다.
- 빌드 산출물에 `sitemap.xml`, `robots.txt`, `feed.xml`이 생성된다.
- front matter 필수 필드가 빠졌거나 slug가 중복되면 빌드가 실패하고, 원인 파일 경로를 출력한다.

### 7. 배포
완료 판정 기준:
- main에 푸시하면 GitHub Actions가 테스트, 빌드, Azure Static Web Apps 배포를 실행한다. PR에서는 테스트만 실행한다.
- 보유한 루트 도메인으로 접속되고(www는 루트로 리다이렉트), HTTPS가 적용된다.
- `/blog/{slug}` 같은 딥링크로 직접 접속하거나 새로고침해도 404가 나지 않는다.

## 범위 밖
- **Playground 실제 구현(Unity WebGL 데모)**: MVP 이후에 한다. 잠긴 행성만 미리 배치한다. 도입할 때 호스팅을 다시 검토한다(ADR-006).
- **글별 OG 태그와 공유 미리보기**: WASM Standalone이라 MVP에서는 사이트 공통 OG만 쓴다. 프리렌더링이나 Web App으로 옮길 때 해결한다(ADR-001).
- **댓글, 검색, 방문자 분석**: 초기에는 글이 적어 효용이 낮다.
- **라이트 모드**: 다크 전용으로 테마 토큰을 한 벌만 관리한다.
- **다국어(i18n)**: 콘텐츠는 한국어, HUD 라벨은 영어로 고정한다.
- **연락 폼, 이력서 PDF**: 정적 사이트에서 서버 없이 링크로 충분하다.
- **PWA·오프라인, 관리자 페이지, DB**: 정적 사이트와 git 기반 발행으로 충분하다.

## 제약
- **기술**: C#/.NET 10 Blazor WebAssembly Standalone, Three.js(TypeScript, Vite). 서버 코드와 DB는 없다. 세부 사항은 ADR.md를 따른다.
- **성능 예산**:
  - 홈 첫 방문 전송량은 3MB 이하(Brotli 기준, .NET 런타임, 앱 어셈블리, 씬 번들, 홈에서 쓰는 폰트 포함).
  - 4G 중급 모바일 기준, 부팅 화면에서 조작 가능해지기까지 4초 이내.
  - 메인 화면은 데스크톱 60fps, 중급 모바일 30fps 이상. 모바일은 devicePixelRatio 상한 1.5에 후처리를 줄인다.
- **브라우저**: WebGL2를 지원하는 최신 Chrome, Edge, Safari(iOS 포함), Firefox. 미지원 환경은 기능 5의 목록형 홈으로 대체한다.
- **언어**: 콘텐츠는 한국어, HUD와 UI 라벨은 영어 대문자다.
- **비용**: Azure Static Web Apps Free 플랜과 보유 도메인만 쓴다. 유료 서비스를 추가하지 않는다.
- **URL 영속성**: 공개한 URL(`/blog/{slug}`, `/projects/{slug}`, `/about`, `/blog/tags/{tag}`)은 호스팅을 옮겨도 바꾸지 않는다. slug는 영문 kebab-case다.
- **저장소**: GitHub 비공개 저장소로 시작하고 안정화되면 공개한다. 공개하면 초안이 커밋 이력에 드러나므로 공개 전에 처리 방식을 다시 정한다.

## 미정 값
- **도메인 이름**: 문서에는 `{DOMAIN}`으로 적는다. 값은 `content/site.yml`의 `baseUrl` 한 곳에만 둔다. 예외로 `index.html`의 OG 태그는 정적이어야 해서 같은 값을 직접 쓰고, 테스트가 `site.yml`과의 일치를 검사한다.
- **천체의 세계관 이름**: UX.md의 이름은 임시다. `content/universe.yml`에서 바꾼다.
